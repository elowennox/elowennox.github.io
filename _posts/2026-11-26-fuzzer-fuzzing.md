## 1. Fuzzing이란?

Fuzzing(퍼징)은 프로그램에 무작위 데이터나 비정상적인 입력값을 반복적으로 전달하여 오류 및 보안 취약점을 발견하는 소프트웨어 테스트 기법이다.

일반적인 테스트가 예상한 입력값에 대해 프로그램이 정상적으로 작동하는지 확인한다면, 퍼징은 예상하지 못한 입력값이 들어왔을 때도 프로그램이 안전하게 동작하는지 확인하는 데 중점을 둔다.

예를 들어 숫자만 입력받도록 설계된 프로그램에 문자열이나 지나치게 큰 숫자를 입력하여 프로그램이 어떻게 반응하는지 확인하는 것이다.

이러한 과정을 통해 프로그램의 비정상 종료(Crash), 메모리 오류, 예외 처리 문제 등을 발견할 수 있다.

### Fuzzer란?

Fuzzer(퍼저)는 퍼징을 자동으로 수행하는 도구이다.

퍼저는 다양한 테스트 입력값을 생성하고 프로그램에 전달한 뒤, 실행 결과를 관찰하여 오류가 발생했는지 확인한다.

즉, Fuzzing은 테스트 기법이고 Fuzzer는 이를 수행하는 도구라는 차이가 있다.

## 2. Fuzzing의 동작 원리

퍼징은 일반적으로 다음과 같은 과정으로 진행된다.

**① 테스트 대상 선정**

취약점을 확인할 프로그램이나 함수를 선정한다.

**② 입력값 생성**

무작위 데이터 또는 기존 데이터를 변형하여 다양한 테스트 입력값을 생성한다.

**③ 프로그램 실행**

생성한 입력값을 프로그램에 전달하여 실행한다.

**④ 실행 결과 확인**

프로그램이 정상적으로 작동하는지, 비정상 종료나 오류가 발생하는지 확인한다.

**⑤ 오류 분석 및 반복**

오류가 발생한 입력값을 저장하여 원인을 분석하고, 새로운 입력값으로 테스트를 반복한다.

일부 퍼저는 프로그램의 코드 커버리지(Code Coverage)를 확인하여 아직 실행되지 않은 코드 영역을 탐색하도록 입력값을 개선하기도 한다.

여기서 코드 커버리지란 테스트 과정에서 프로그램의 코드가 얼마나 실행되었는지를 나타내는 지표이다.

## 3. Fuzzing의 종류

퍼징은 입력값을 생성하는 방식과 프로그램 내부 정보를 활용하는 정도에 따라 구분할 수 있다.

### 3.1. 입력값 생성 방식에 따른 분류

**① Mutation-based Fuzzing (변이 기반 퍼징)**

기존에 존재하는 정상적인 입력값을 변형하여 새로운 테스트 데이터를 만드는 방식이다.

예를 들어 `HELLO`라는 문자열을 `HE!LO`, `HELL0` 등으로 변경하여 프로그램에 입력할 수 있다.

- 장점: 기존 데이터를 활용하므로 비교적 쉽게 테스트를 시작할 수 있다.
- 단점: 초기 입력값의 품질에 따라 테스트 범위가 제한될 수 있다.

**② Generation-based Fuzzing (생성 기반 퍼징)**

입력 데이터의 형식이나 규칙을 바탕으로 새로운 테스트 데이터를 생성하는 방식이다.

예를 들어 특정 네트워크 프로토콜의 메시지 구조를 정의하고, 각 필드에 다양한 값을 넣어 테스트할 수 있다.

- 장점: 정해진 형식에 맞는 다양한 입력값을 생성할 수 있다.
- 단점: 데이터 형식이나 프로토콜 구조에 대한 이해가 필요하다.

### 3.2. 내부 정보 활용 정도에 따른 분류

| 종류 | 특징 |
|---|---|
| Black-box Fuzzing | 프로그램 내부 구조를 알지 못한 상태에서 입력과 출력 등을 관찰하며 테스트 |
| Gray-box Fuzzing | 코드 커버리지와 같은 일부 실행 정보를 활용하여 테스트 |
| White-box Fuzzing | 프로그램 내부 구조와 코드 분석 정보를 적극적으로 활용하여 테스트 |

Black-box 방식은 내부 정보를 몰라도 테스트할 수 있다는 장점이 있다.

Gray-box 방식은 실행 과정에서 얻은 정보를 바탕으로 새로운 코드 경로를 탐색할 수 있어 효율적인 테스트가 가능하다.

White-box 방식은 프로그램 내부 동작을 자세하게 분석할 수 있지만 분석 과정에서 더 많은 자원이 필요할 수 있다.

## 4. 대표적인 Fuzzer

### 4.1. AFL++ (American Fuzzy Lop Plus Plus)

AFL++는 코드 커버리지를 활용하는 대표적인 퍼징 도구이다.

프로그램에 다양한 입력값을 전달하고, 실행 과정에서 새로운 코드 경로가 발견되면 해당 입력값을 활용하여 추가적인 테스트를 수행한다.

**주요 특징**
- 코드 커버리지 기반의 퍼징 수행
- 기존 입력값을 변형하는 방식 활용
- 프로그램의 다양한 실행 경로 탐색
- 비정상 종료 및 오류 발생 입력값 저장

AFL++는 프로그램 실행 경로를 탐색하면서 메모리 오류나 비정상 종료 등을 발견하는 데 활용할 수 있다.

### 4.2. libFuzzer

libFuzzer는 LLVM 프로젝트에서 제공하는 코드 커버리지 기반 퍼징 엔진이다.

주로 C/C++ 프로그램의 특정 함수나 라이브러리를 테스트하는 데 사용된다.

테스트 대상 함수와 퍼징 엔진을 하나의 프로세스에서 실행하는 In-process 방식이 특징이다.

**주요 특징**
- LLVM 기반의 퍼징 엔진
- 코드 커버리지 기반으로 입력값 개선
- 특정 함수나 라이브러리 테스트에 적합
- AddressSanitizer 등의 오류 탐지 도구와 함께 활용 가능

libFuzzer는 프로그램 전체보다는 특정 함수나 라이브러리의 입력 처리 과정에 집중하여 테스트할 때 유용하다.

### 4.3. boofuzz

boofuzz는 네트워크 프로토콜을 테스트하기 위한 퍼징 프레임워크이다.

네트워크를 통해 다양한 형태의 메시지를 전달하고, 대상 프로그램이나 장비에서 오류가 발생하는지 확인하는 데 활용할 수 있다.

**주요 특징**
- 네트워크 프로토콜 퍼징에 특화
- 메시지 구조 및 필드를 정의하여 테스트 가능
- Python 기반의 퍼징 프레임워크
- 네트워크 서비스 및 장비 테스트에 활용

특히 서버나 네트워크 장비가 비정상적인 메시지를 받았을 때 어떻게 반응하는지 확인하는 데 유용하다.

## 5. Fuzzer 비교

| 구분 | AFL++ | libFuzzer | boofuzz |
|---|---|---|---|
| 주요 대상 | 프로그램 및 바이너리 | 함수 및 라이브러리 | 네트워크 프로토콜 |
| 주요 방식 | 커버리지 기반 | 커버리지 기반 | 프로토콜 구조 기반 |
| 특징 | 실행 경로 탐색 | 함수 단위 테스트 | 네트워크 메시지 테스트 |
| 활용 예시 | 파일 처리 프로그램 | C/C++ 라이브러리 | 서버 및 네트워크 장비 |

AFL++와 libFuzzer는 코드 커버리지를 활용한다는 공통점이 있지만, 일반적인 실행 방식과 테스트 대상을 구성하는 방법에 차이가 있다.

반면 boofuzz는 네트워크 메시지의 구조를 정의하고 다양한 입력값을 전달하는 데 중점을 둔다.

따라서 퍼저를 선택할 때는 테스트 대상과 목적을 고려해야 한다.

## 6. Fuzzing의 장단점

### 6.1. 장점

**① 자동화된 취약점 탐지**

수많은 입력값을 자동으로 생성하고 테스트할 수 있어 반복적인 작업을 줄일 수 있다.

**② 예상하지 못한 오류 발견**

개발자가 미처 고려하지 못한 입력값을 테스트하여 숨겨진 오류를 발견할 수 있다.

**③ 다양한 프로그램에 적용 가능**

파일 처리 프로그램, 라이브러리, 네트워크 서비스 등 여러 분야에 활용할 수 있다.

### 6.2. 단점

**① 많은 시간과 자원 필요**

수많은 입력값을 반복적으로 테스트하므로 실행 시간이 길어지고 컴퓨팅 자원이 많이 사용될 수 있다.

**② 모든 취약점 탐지 불가능**

퍼징만으로 모든 코드 경로와 보안 취약점을 확인할 수는 없다. 특히 복잡한 논리적 취약점은 발견하기 어려울 수 있다.

**③ 발견한 오류에 대한 추가 분석 필요**

프로그램에서 비정상 종료가 발생하더라도 반드시 보안 취약점이라는 의미는 아니다. 실제 취약점인지 확인하려면 원인 분석이 필요하다.

## 7. Fuzzing의 활용 분야

퍼징은 소프트웨어 보안 점검뿐만 아니라 다양한 환경에서 활용된다.

- **소프트웨어 보안:** 프로그램의 입력값 처리 오류 및 메모리 취약점 탐지
- **네트워크 보안:** 비정상적인 네트워크 패킷이나 프로토콜 메시지 처리 테스트
- **임베디드 보안:** 펌웨어 및 임베디드 장치의 입력 처리 안정성 점검
- **버그바운티:** 허가된 테스트 범위에서 잠재적인 취약점 탐색

특히 임베디드 시스템이나 네트워크 장비는 잘못된 입력값으로 인한 오류가 시스템의 안정성에 영향을 줄 수 있기 때문에 퍼징이 유용하게 활용될 수 있다.

## 8. 마무리

이번 학습을 통해 Fuzzing은 비정상적이거나 예상하지 못한 입력값을 반복적으로 전달하여 프로그램의 오류와 취약점을 발견하는 테스트 기법이라는 것을 알게 되었다.

또한 Fuzzer는 이러한 과정을 자동화하는 도구이며, AFL++, libFuzzer, boofuzz처럼 테스트 대상과 목적에 따라 다양한 종류가 존재한다는 점을 확인했다.

퍼징은 개발자가 예상하지 못한 문제를 발견할 수 있다는 장점이 있지만, 모든 취약점을 찾아내는 것은 아니므로 다른 보안 테스트 기법과 함께 활용하는 것이 중요하다고 생각한다.
